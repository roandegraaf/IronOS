Key decisions:
- **Hero font: a generated bitmap table, not the translation font tables.**
  - Digits aren't translatable text, so routing them through `make_translation.py` would only add a Docker dependency.
  - Terminus (the bundled OFL font) tops out at 32 px with digits about 20 px tall, too short for a hero.
  - Rasterising SF Pro, Helvetica or Arial was rejected for licensing reasons.
  - So the digits are an original squared-off design: 16x28 ink, 4 px strokes, outer corner radius 5, rasterised at 8x and box-filtered to 1 bit. Cells are 16x32 plus a 2 px gap; the degree glyph is an 8x8 ring.
  - Cost: 704 B font, 16 B degree glyph, 16 B bolt.
- Hero digits are drawn with `drawArea` per glyph. They avoid `printNumber`/`drawChar`, whose leading-zero stripping indexes the large font table, and need no new `FontStyle` in the shared `OLED.cpp`.
- Icons are 8x16 ASCII art in the generator, stored in the same generated `.cpp`, not in `Font.h` (per-TU header copies).

Notes / leftovers:
- On lithium-cell DC (`MinDCVoltageCells` set), DENSE showed a battery gauge. The hero screen shows bolt plus voltage until the battery icon lands.
- Hero glyphs are blitted with `drawArea` over all 32 rows of their columns (ink rows 2..29), so they erase anything drawn there earlier. Soldering detailed's bottom power bar runs under the hero and needs one of these: rows 30–31 only, the bar drawn after the hero with digit ink kept clear (≥ row 30), a shorter hero variant, or an OR-blit helper.
- `ui_draw_hero_icon` only draws at y=0. Add a y parameter if a later icon needs the lower half.
- The firmware and preview builds both compile `hero_font.cpp`/`hero_ui.cpp` via the existing directory globs; no script changes were needed.

Key decisions:
- Icon selection uses `getIsPoweredByDCIN()`, not `getPowerSourceNumber()`, so unnegotiated USB-C (reported as "QC") also gets the USB-C icon.
- Battery fill is drawn at runtime over a generated outline rather than ten generated level icons.
- Icons are never flipped for LH: the panel rotation already shows them upright to a left-handed user; only their position goes through `hero_x()`.
