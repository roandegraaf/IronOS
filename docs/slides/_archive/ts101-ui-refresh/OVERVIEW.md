# TS101 UI refresh (personal fork)

## Goal
A personal IronOS fork for one specific Miniware TS101 (older OLED panel batch), with a modern "big-number hero" UI. The idle and soldering screens are redesigned (both the detailed and simplified variants) and the icons and fonts are refreshed. A host-side preview renderer makes design iteration possible without reflashing the iron through Miniware's flaky bootloader each time.

## Scope
- Make current `dev` render correctly on this unit's panel again (it currently renders shifted/cut off).
- An EN-only TS101 build plus a one-command build-and-flash helper for macOS.
- A host-side preview renderer that turns the real `mono_128x32` drawing code into PNGs of each screen in fixture states, on the Mac with no hardware.
- A new layout for each of these screens, in the "big-number hero" style:
  - idle, simplified
  - idle, detailed
  - soldering, simplified
  - soldering, detailed
- A large hero-digit font, crisper small fonts, and a new icon set: heat, boost, power source/PD, sleep, battery.
- Left-handed (rotated) mode keeps working on all redesigned screens.

## Non-goals
- Languages other than EN (no font coverage or layout checks for them).
- Redesigning the settings menu, debug menus, warnings or the boot logo. These only need to keep rendering legibly with any changed fonts.
- Changing how the Sequre S60/S60P/T55/S99 look. They share `mono_128x32`, but the new UI is opt-in for TS101.
- Fixing USB-PD or reboot behaviour, and newer-panel support.
- Upstreaming to Ralim/IronOS.

## Key decisions & constraints
- **Panel fix:** this unit's panel works with v2.23. Commit `2e1f8c22` enables `OLED_DISPLAY_OFFSET_QUIRK` (0xD3 offset 0x30) and `OLED_I2C_PER_BYTE_TRANSFERS` for every TS101 in `source/Core/BSP/Miniware/configuration.h`. In the fork these become opt-in (default off), so this panel gets the pre-quirk behaviour. Also check the full-screen change from #2225, since v2.23 predates it.
- **Opt-in UI flag:** the new UI is gated behind its own flag (for example `OLED_128x32_HERO_UI`), set only in the TS101 block of the Miniware `configuration.h`. Existing `OLED_128x32_DENSE_UI` and upstream code paths stay intact for the other models, which keeps rebasing on upstream `dev` cheap.
- **Building:** in Docker on macOS. Plain `make docker-build` fails on GID 20, so use this:
  `HOST_UID=$(id -u) HOST_GID=1000 docker compose -f Env.yml run --rm builder bash -c "cd source && make -j8 model=TS101 firmware-EN"`
  Output goes to `source/Hexfile/TS101_EN.hex`.
- **Flashing:**
  1. Hold the front button while plugging into the Mac; the iron mounts as `/Volumes/TS101_DFU`.
  2. Copy the hex with `cp -X` (no `._` extended-attribute files).
  3. Wait for the file to be renamed to `.RDY` (success) or `.ERR`.
  4. Run `diskutil eject`.
- **Power for testing:** the Mac USB port (5 V, about 15 W) makes the iron reboot-loop with a tip in. Hardware tests with a tip need a USB-C PD charger (45 W or more) or the DC jack.
- **Display:** 128x32, one-bit. The framebuffer and fonts live in `source/Core/Drivers/OLED.cpp/.hpp` and `Font.h`. Fonts are generated by `Translations/font_tables.py` and `make_translation.py`. Screens are in `source/Core/Threads/UI/drawing/mono_128x32/`, and logic is in `.../UI/logic/`.
- **Flash budget:** the TS101 ROM region is 66 KB. The EN build currently uses about 50.4 KB, so roughly 16 KB is left. RAM is at 71% of 20 KB. Every new font or icon must fit.
- **Preview renderer:** compiles the real drawing code and `OLED` framebuffer with host clang against thin stubs (RTOS, I2C, settings, power, sensors). Fixture states are data, not hand-drawn. Output is PNG, upscaled 4x, white on black.
- **Chosen layouts:** the user picked these from the mockup page `.mockups/ts101-hero-screens.html` (option B or A per screen). Pixel positions may be tuned in the design slices; the structure is fixed.

  | Screen | Pick | Layout |
  | --- | --- | --- |
  | Idle, simplified | B | live tip temp hero left; bolt icon + input voltage top-right; set point in an inverted (filled) box bottom-right |
  | Idle, detailed | A | hero tip temp left; 1px vertical divider; three label/value rows right (SET 320°, PD 20.1V, HND 31°) |
  | Soldering, simplified | B | hero tip temp left; vertical stepped heat column at the far right (button side); small "→320" set point beside it |
  | Soldering, detailed | A | hero tip temp left; watts in 2x small font top-right; "→320° 20.1V" below it; full-width outlined power bar along the bottom |

- **Boost indicator:** the chosen soldering-simplified layout has no slot for it yet. Implemented: during boost, the set point shows the boost temperature with a double-chevron boost glyph instead of "→" (slice 8 replaced the original up-arrow). Awaiting user confirmation.

## Preconditions & external dependencies
- **Docker Desktop running:** already available.
- **The TS101 and a USB data cable to the Mac:** the user physically enters DFU mode for every flash.
- **A USB-C PD charger (45 W or more) or a DC supply:** needed for hardware tests with a tip.
- **Optional GitHub fork (`roandegraaf/IronOS`):** only needed to push the fork. `origin` currently points at Ralim/IronOS. Work happens locally on a branch until the user decides.

## Building blocks
- Panel quirk gating in the Miniware `configuration.h` and `OLED.cpp`
- Build-and-flash helper script for macOS
- Host preview renderer, with stubs, fixtures and PNG output
- Hero digit font and refreshed small font, generated through the font tables
- Icon set in `Font.h` and the `drawSymbol` / `drawHeatSymbol` helpers
- New `mono_128x32` drawing paths for home (detailed and simplified) and soldering (basic and power status), behind the hero UI flag
